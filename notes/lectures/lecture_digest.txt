-- CONVENTIONS
  * Data matrix X is T x n (rows = observations/time, columns = variables). A PC Z_j = X gamma_j is a T-vector (factor time series). Loadings gamma_j are n-vectors. [ L1 p.42, p.45, p.73-74 ]
  * Demean every column before PCA ('Remember: X has been centered'). [ L1 p.45, p.63 ]
  * Sample covariance for PCA is Sigma-hat = X'X / T (divide by T, not T-1). Note that exam Problem 2 explicitly overrides this with var(ddof=1). [ L1 p.63 ]
  * PC loadings are unit-norm and mutually orthogonal. PCs are uncorrelated, ordered by eigenvalue (largest first), and the variance of PC j equals lambda_j. The covariance of the first k PCs is diag(lambda_1..lambda_k). [ L1 p.64-74 ]
  * PCA is classified as unsupervised learning, for dimension reduction, noise reduction and pre-treatment for later ML models. [ L1 p.25, p.46 ]
  * Scree plot (eigenvalues vs PC number) is the visual tool for how many PCs matter. No formal k-selection rule is given in L1. [ L1 p.43 ]
  * Correlation = Cov/(sd*sd). The first look at a wide dataset is the correlation matrix via df.corr(), displayed as a heat map. Always pair correlation with a scatter plot. [ L1 p.44 ]
  * Every result needs a benchmark: 'A number with no benchmark is not a result'; 'Is 0.72 good? Compared to what?' [ L1 p.81, p.82 ]
  * For a monthly time series, the future must not end up in the training set (time-ordered splitting). [ L1 p.82 ]
  * Frame first: a forecast, a treatment effect and a trading signal are different questions requiring different setups. Validation requires knowing where the data came from (ask what the data are). [ L1 p.81, p.82 ]
  * AI tools may be used on everything and should write the code, but the student owns framing, validation and judgment. Lecture 0 and AI_Coding_Guide.pdf govern good use. [ L1 p.81-82 ]
  * Expect low signal-to-noise in return prediction (market efficiency). Finance samples are short (100s of months) and nonstationary. n~p makes OLS infeasible. [ L1 p.33-34 ]
  * Class data lives at /classes/41210_MiF_fall2026/ on Booth JupyterHub (matches the exam _DATA_DIR). [ L1 p.3 ]

################ L2: Lecture 2: Linear Regression Models (Simple Linear Regression, CAPM/single-factor, sampling distributions, CLT, standard errors via simulation/bootstrap, CIs, hypothesis tests, prediction intervals)
TOPICS: Linear regression setup and prediction rule (3-10, 33-36) | Ordinary least squares (simple regression): estimator and closed form (11-18, 24-25, 45) | Orthogonality of fitted values and residuals (19-23) | ANOVA decomposition and in-sample R^2 (26-32) | Simple linear regression probability model (37-46) | Single-factor (index) model and CAPM (47-54) | Error variance estimation and degrees of freedom (55-58) | Sampling distributions and the Central Limit Theorem (59-70) | Sampling distribution of b1 and b0; bias vs variance; standard errors (71-77) | What a standard error really is: formula vs parametric simulation vs bootstrap (78-80) | Student t distribution and confidence intervals (81-87) | Hypothesis testing, t-statistics, p-values (CAPM alpha and beta tests) (88-97) | Prediction intervals (98-106)
-- CONVENTIONS
  * Variances and standard deviations are always computed with ddof=1: np.var(..., ddof=1) and np.std(..., ddof=1). The unbiased estimator divides by n-1 for a sample variance and by n-p for the regression error variance. [ L2 p.17, 31, 32, 56-57, 106 ]
  * Degrees of freedom = n - p. They are the number of real observations of variability left after estimating p coefficients. statsmodels model.scale = SSE/(n-p) and model.df_resid = n-p. [ L2 p.56-58 ]
  * House style is the statsmodels formula API smf.ols('Y ~ X', data).fit() with .params, .bse, .resid, .fittedvalues, .scale, .summary(), .conf_int(), .get_prediction(). anova_lm is used for ANOVA. scipy.stats.t.ppf and t.cdf are used for critical values and p-values. sklearn LinearRegression is named as an alternative. [ L2 p.16, 18, 31, 53, 58, 87, 95, 97, 106 ]
  * Inference uses t_{n-p} critical values, not z, when sigma is estimated. About 2 standard errors is the 95% rule of thumb. [ L2 p.44, 81-85, 91 ]
  * Factor and CAPM regressions use excess returns r_i - r_f on r_M - r_f. Alpha is the performance benchmark and CAPM implies alpha = 0. The T-bill is given annualized in percent. [ L2 p.47-50 ]
  * R^2 is in-sample: R^2 = SSR/SST = 1 - SSE/SST, implicitly benchmarked on the in-sample mean Ybar. In SLR it equals r_xy^2. [ L2 p.29-30 ]
  * Population quantities (beta, eps) are distinguished from sample estimates (b, e). [ L2 p.46 ]
  * A standard error is defined as the spread of the estimate across hypothetical re-runs. It is checked by formula, by parametric simulation from the fitted model, and by resampling the actual data with replacement. Discrepancies measure 'the size of the assumption'. [ L2 p.78-80 ]
  * Commit-before-compute: write down a numerical prediction before running the simulation. [ L2 p.78 ]
  * Default statsmodels t and p values test H0: beta = 0 with nonrobust covariance. Tests of other nulls (e.g. beta = 1) are computed manually. [ L2 p.32, 53, 97 ]
  * A prediction interval for a new observation uses s_pred = sqrt(s^2 + s_fit^2), i.e. obs_ci. A CI for the conditional mean uses s_fit only, i.e. mean_ci. [ L2 p.101-106 ]
-- PITFALLS
  ! If residuals are correlated with X, predictive ability has been left on the table. The 'crazy line' 10+50X gives corr(e,X) = -0.7 and mean(e) = 1.8. [ L2 p.21-23 ]
  ! Acronym trap: SSR can mean regression SS or residual SS. (Outside the slides: statsmodels .ssr is the residual SS and .ess is the explained SS.) [ L2 p.28 ]
  ! beta0 is not b0, beta1 is not b1, and eps_i is not e_i. Do not confuse the true line with the estimated line. [ L2 p.46 ]
  ! The fitted line 'may be fooled by particular realizations of the residuals'. [ L2 p.36 ]
  ! With small n, estimates vary a lot across samples ('we need to get lucky', N=5 vs N=50). [ L2 p.59-62 ]
  ! Large sigma is bad. Precision of b1 depends on n, sigma^2 and the X-spread s_x. An unbiased estimator can still have high variance (bias vs variance). [ L2 p.71-73 ]
  ! Leverage: b1 is weighted more heavily by X_i far from Xbar. [ L2 p.74 ]
  ! Estimation errors in b0 and b1 are negatively correlated when Xbar > 0. [ L2 p.76 ]
  ! Textbook SEs assume normal, independent, equal-variance errors. Weekly equity returns violate this ('calm months and panics do not have the same variance'), and the textbook SE is about 7% too small vs the bootstrap. This is why practitioners report robust SEs. 'The first time ... a formula and the data have disagreed. It will not be the last.' [ L2 p.80 ]
  ! Parametric simulation from the fitted model only reproduces the model's own assumptions. It agreed with the formula to 0.3%, and only resampling the real data revealed the gap. [ L2 p.79-80 ]
  ! The t distribution is fat-tailed relative to the normal. Use t_{n-p} critical values when sigma is estimated. [ L2 p.81 ]
  ! statsmodels' default t/p values test beta = 0 and are the wrong numbers for testing beta = 1. Compute (b1-1)/s_b1 by hand. [ L2 p.97 ]
  ! alpha is the type I error rate (the probability of rejecting a true null). [ L2 p.93 ]
  ! The prediction interval must include estimation error as well as noise, and it widens with (X_f - Xbar)^2. Extrapolating far from the data centre is much less certain. [ L2 p.100-105 ]
  ! Square before summing: s_pred = sqrt(s^2 + s_fit^2), not s + s_fit. Do not confuse mean_ci (CI of the mean) with obs_ci (PI of an observation). [ L2 p.106 ]
  ! Slide inconsistencies and typos: p.78 has b1 = 1.0923 while p.53/95 have 1.0893. p.29 states 0 < R^2 (in-sample R^2 >= 0). p.12 writes X1 for X_i. p.106 pd.DataFrame('SPX': [0.75]) is missing braces and t_critical is undefined. p.87 params[0] positional indexing is deprecated in modern pandas. [ L2 p.12, 29, 53, 78, 87, 106 ]

-- CONVENTIONS
  * log means the natural log (ln); any other base is labelled explicitly (e.g., log2) [ L3 p.49 ]
  * p counts the intercept (p = d+1; p = 2 in SLR). Residual variance s^2 = SSE/(n-p). t-based CIs, tests and prediction intervals use n-p df; studentized residuals use n-p-1 [ L3 p.14, 15, 24, 30, 35, 37 ]
  * Diagnostics are graphical first: residuals e (or studentized r) vs fitted Yhat or X are the #1 tool, supplemented by a yhat-vs-y fit plot [ L3 p.3, 8, 18, 58 ]
  * Outlier flag: externally studentized residual outside about [-2.5, 2.5] (t_{n-p-1} reference) [ L3 p.16 ]
  * Outlier policy: delete only with a really good reason; run with and without; always state the reasons for any dropped observations [ L3 p.17 ]
  * MLR coefficients are partial effects 'holding all other variables constant'. Inference on b_j is conditional on the rest of the model and one-at-a-time [ L3 p.21, 29, 35 ]
  * Categorical factor with R levels -> R-1 treatment dummies; the reference level (first level, e.g., dominicks) is absorbed by the intercept, and coefficients are 'change relative to reference' [ L3 p.45, 51-52 ]
  * Interactions are specified with `*` in the statsmodels formula (main effects plus products). The effect of x_j is beta_j + x_k beta_jk [ L3 p.53-54 ]
  * Use log(y) when y changes on a percentage scale. Log-log slopes are elasticities (% change in y per 1% change in x) [ L3 p.49-50 ]
  * House style: statsmodels formula API smf.ols(...).fit(); predict/get_prediction on a DataFrame with the same variable names and factor levels as the training data; sm.add_constant + numpy for manual matrix calculations; scipy t.ppf for critical values [ L3 p.7, 26, 28, 38 ]
  * Prediction intervals include both parameter uncertainty and noise: s_pred^2 = s^2 + s_fit^2. obs_ci columns of summary_frame are the PI, mean_ci the CI for the mean [ L3 p.37-38 ]
  * Default (nonrobust) OLS standard errors are used throughout; S_b = s^2 (X'X)^{-1} [ L3 p.28, 33, 42 ]
-- PITFALLS
  ! Inference and prediction rely on the model being true. If the assumptions fail, predictions can be systematically biased and SEs, intervals and t-tests are wrong [ L3 p.3 ]
  ! Identical summary statistics, regression lines and R^2 can hide completely different data (Anscombe). Always plot data and residuals [ L3 p.4-8 ]
  ! One big outlier makes s overestimate sigma and can mask itself. Use studentized (leave-one-out) residuals [ L3 p.14-15 ]
  ! High-leverage outliers are hard to catch with r_i because the line is pulled toward them. Outliers do more damage with high leverage; plot r_i or e_i vs Yhat or X [ L3 p.12, 18 ]
  ! Do not delete outliers without a really good reason; document any drops and compare results with and without [ L3 p.17 ]
  ! Multicollinearity: the marginal-effect interpretation is lost, SEs are large and coefficients unstable (adding or dropping variables changes the others; the lty sign flips). Individual t-tests can all be insignificant while the joint F is significant [ L3 p.39-43 ]
  ! With exactly collinear regressors (X2 = 10 X1) the effects cannot be separated. [Own observation] The Welch-Goyal full regression silently has rank deficiency (Df Model 14 < 16 because d_e = d_p - e_p and tms = lty - tbl) [ L3 p.40, 27-28 ]
  ! Multicollinearity does not by itself hurt fit or (in-sample) prediction, but beta_j are not true marginal effects; consider dropping variables via the partial F-test [ L3 p.44 ]
  ! Dummy-variable trap: do not include all R dummies together with an intercept [ L3 p.52 ]
  ! Think about the scale on which linearity holds; skewed raw scatters call for logs (and a check for outliers) [ L3 p.48-49 ]
  ! Confounding: omitting a correlated driver (feat/promotion) distorts group-level estimates (brand elasticities) [ L3 p.57 ]
  ! Plot yhat vs y to check misspecification (non-constant variance, nonlinearity) [ L3 p.58 ]
  ! New data passed to predict must have exactly the same format as the training data (variable names, factor levels) [ L3 p.26 ]

################ L4: Model Evaluation and Selection
TOPICS: Model evaluation vs model selection (3, 43) | Overall F-test for regression significance (4-7) | R^2 inflation, overfitting and adjusted R^2 (9-10, 28) | Partial F-test (nested models) (11-15) | F-test vs t-test and multicollinearity (16-21) | Variable selection principles (Ockham's razor) (22-24) | Multiple testing, the noise-predictor experiment, Bonferroni/max-t (25-28) | Information criteria: AIC, BIC, BIC model probabilities (29-33) | Subset selection (34) | Correlation screening (35-39, 49-50) | Forward stepwise regression (AIC) (40-41, 49-50) | Training / validation / test design (42-43) | In-sample vs out-of-sample R^2 (course benchmark convention) (44-48) | Sensitivity of selection to the sample (49-50)
-- CONVENTIONS
  * R^2_OOS is a comparison of the SSEs of two predictors. The default benchmark in the denominator is the IN-SAMPLE (training) mean of Y, never the out-of-sample mean. Zero (or another in-sample estimator) is also an acceptable benchmark. R^2_OOS can be negative. [ L4 p.45-46 ]
  * For time-series data, the holdout is the LAST 20% of observations (chronological 80:20 split, leaveout = range(4*N//5, N)). The model is fit once on the first 80% and there is no shuffling. [ L4 p.47-48 ]
  * OOS R^2 code pattern: 1 - sse(y_test, y_pred)/sse(y_test, y_train.mean()). [ L4 p.47-48 ]
  * Train/validation/test roles: training fits parameters, validation selects models or hyper-parameters, and the test set stays untouched until final evaluation. Validation is a 'gray zone'. [ L4 p.43 ]
  * Prefer the simplest adequate model (Ockham's razor; 'always use the simplest model possible'; add covariates only if truly informative). [ L4 p.11, 23 ]
  * Judge models by prediction, not fit: 'stop asking whether it fits and start asking whether it predicts'. Report the size of the search next to any result. [ L4 p.28 ]
  * Information criteria use p = d+1 (intercept counted): BIC = n log s^2 + p log n, AIC = n log s^2 + 2p. Choose the minimum. BIC is preferred ('best of these'), gives model probabilities and yields simpler models. [ L4 p.29-33 ]
  * Nested model comparison uses the partial F-test via anova_lm(small, big). Degrees of freedom come from the fitted df_model (rank). [ L4 p.14-15 ]
  * Regressions use the statsmodels formula API (smf.ols with a '+'.join(columns) formula string) and .summary()/.rsquared/.aic/.bic/.predict. [ L4 p.7, 14, 30, 36, 47 ]
  * Multiple-testing correction is done by changing the critical value (Bonferroni / max-t: 3.65 for 100 tests), not by using a different fit statistic. [ L4 p.28 ]
-- PITFALLS
  ! In-sample R^2 always increases with more regressors. Least squares fits noise (overfitting), so better fit does not mean better prediction. [ L4 p.9 ]
  ! Adjusted R^2 is 'practically useless': it has no inference theory, and it gave 0.31 on 10 pure-noise predictors selected by search. It does not protect against having searched. [ L4 p.10, 28 ]
  ! Multiple testing: 20 true-null tests at 5% give about one false positive. With 10% true signals about 1/3 of discoveries are false. With 100 noise predictors, P(>=1 significant) = 99.6% and the best noise t was 2.88. Use a search-adjusted critical value (3.65 for 100) and report the search size. [ L4 p.25-28 ]
  ! Multicollinearity inflates standard errors, so all individual t-tests can fail while the joint F is significant. Conversely, a significant t can coexist with an insignificant F. Don't select variables by individual t-stats. [ L4 p.19-21 ]
  ! Testing-based selection works only for a small, intelligently chosen candidate set. Information criteria also require narrowing the options first. Best subset needs 2^p fits. [ L4 p.24, 33, 34 ]
  ! Correlation screening keeps redundant variables, omits variables that matter only jointly, and causes post-screening multicollinearity. Individually useful does not mean collectively useful. [ L4 p.39 ]
  ! Stepwise selection is myopic and unstable (high sampling variability). Dropping one year of data changes the selected sets (screening 33 to 30, forward 36 to 41). [ L4 p.41, 50 ]
  ! The test set must remain untouched until final evaluation, or performance estimates are biased. The validation score of the selected configuration is in the 'gray zone'. [ L4 p.43 ]
  ! Do not use the out-of-sample mean as the R^2_OOS benchmark (rhetorical 'Why not out of sample Ybar?'). It uses information unavailable at forecast time. [ L4 p.46 ]
  ! Kitchen-sink models can have decent IS R^2 but negative OOS R^2 (equity premium 0.476 vs -0.118; macro 0.528 vs -0.501). In-sample criteria (AIC/BIC) preferred forward selection while OOS preferred screening. [ L4 p.47-49 ]
  ! AIC prefers more complicated models than BIC. Subtract BIC_min before exponentiating for numerical stability. [ L4 p.30-31 ]
  !   ! Slide typo: the SSE form of the partial F is written (SSE_full - SSE_base). The correct numerator is SSE_base - SSE_full. [ L4 p.13, 16 ]
  ! Naming trap: statsmodels anova_lm 'ssr' is the residual sum of squares (the slides' SSE), while the slides' SSR on p.5 is the regression sum of squares. [ L4 p.5, 15 ]
  ! My inference: the slides do not show whether screening and forward selection were run on the training subsample only. In exam work, do all selection within the training window, or OOS R^2 has look-ahead. AIC/BIC are comparable only on the same n. The p.50 random-drop code has no seed, so set seeds. [ L4 p.49-50 ]

################ L5: Regularization for Linear Models: Ridge & Lasso (plus CV, information criteria, time-series OOS design, R2_OOS reporting, leakage checklist)
TOPICS: Maximum likelihood and deviance (L5 p.3-5) | Motivation for regularization: OLS variance and bias-variance tradeoff (L5 p.6-10) | General penalized regression and penalty options (incl. elastic net formula) (L5 p.11) | Ridge regression (L5 p.12-16) | Lasso: objective, sparsity, geometry, thresholding (L5 p.17-20) | Lasso path algorithm and path plots (L5 p.21-22, 24) | Scale matters / covariate standardization (L5 p.23, 27, 47) | Prediction vs interpretability; parsimony; prediction-driven model selection (L5 p.25-26) | Design of OOS experiments (four considerations) (L5 p.27) | K-fold cross-validation for iid data and CV-lasso (L5 p.28-36) | Macro forecasting example: effect of the alpha grid (L5 p.37-40) | Problems with CV (L5 p.41) | Information criteria: AIC and BIC (L5 p.42-46) | Time-series CV: expanding and rolling windows; recursive train/validation/test (L5 p.48-51) | Per-window lasso tuning on validation and test prediction (expanding-window lasso) (L5 p.52-54) | Out-of-sample R^2 definition and benchmark (L5 p.55, 57) | Cost of the wrong fold (random vs expanding vs rolling) (L5 p.56) | Leakage checklist and AI-code warnings (L5 p.58-59) | Ridge or LASSO choice (L5 p.60)
-- CONVENTIONS
  * Loss/fit criterion is deviance = -2 log LHD (+C). Gaussian deviance = SSE, and MSE = deviance/n. CV and model comparison are done on out-of-sample deviance/MSE. [ L5 p.4-5, 26, 35-36, 52 ]
  * Penalized objective written as -(2/n) log LHD(beta) + lambda sum_j pen(beta_j); ridge = beta^2, lasso = |beta|, elastic net = alpha beta^2 + (1-alpha)|beta| (slide alpha weights L2, opposite of sklearn l1_ratio). [ L5 p.9, 11 ]
  * Standardize covariates before penalizing (penalty per 1-SD effect). Scale AFTER splitting, fitting the scaler on training data only. In course code y is standardized too and predictions are inverse-transformed to y units. [ L5 p.23, 27, 47, 52, 59 ]
  * Tuning grid is log-spaced with 50 points (2**np.linspace(a,b,50) or 10**np.linspace(a,b,50)). The chosen value must fall in the middle of the grid, not at an edge. [ L5 p.27, 37-39, 53 ]
  * For iid data use K-fold CV with K = 5-10 (LOOCV too slow). Choose lambda minimizing average validation MSE across folds, then refit on all data at lambda-hat. [ L5 p.28, 35, 36 ]
  * For time series, random K-fold is not valid. Use an expanding window (fixed starting point, growing training set) or a rolling window, ordered train -> validation -> test in time. Choose alpha per window on the validation block only and predict the following test block. Example: initial train 180 months, validation 84, test 12, step 12. [ L5 p.48-52 ]
  * R2_OOS = 1 - Dev(model)/Dev(benchmark) on the test predictions, with the benchmark a trailing mean (p.55) or zero (p.56-57), stated explicitly. The test-block mean is not a legitimate benchmark. (The final notebook requires both a per-month trailing mean through t-1 and zero.) [ L5 p.55-57 ]
  * Report negative R2_OOS as a result; never switch benchmarks after the fact; report the size of the specification search next to the number; sanity-check against 0.3-0.5% monthly stock-level R2_OOS. [ L5 p.57 ]
  * Parsimony: if two models predict unseen data about equally well, choose the simpler one. [ L5 p.25 ]
  * AIC = IS deviance + 2 df; BIC = IS deviance + log(n) df; df = number of nonzero coefficients for lasso/MLE. AIC is only reliable for big n/df. [ L5 p.42-44 ]
  * Never use the same data twice (selection and validation). Test data never enters model construction or alpha selection. [ L5 p.41, 52, 55 ]
  * Five-item leakage checklist; item 1 (transformation fitted before split) and item 3 (random fold on time-ordered data) are graded as FATAL. [ L5 p.58 ]
-- PITFALLS
  ! OLS variance sigma^2(X'X)^-1 explodes as p approaches n; MLE is unavailable when p >= n, unstable, and gives no exact zeros. [ L5 p.6, 9 ]
  ! Penalization is scale-sensitive; unstandardized covariates are penalized unfairly. [ L5 p.23 ]
  ! Small datasets: putting too much data in validation hinders training. [ L5 p.27 ]
  ! A bad alpha grid gives a boundary solution: a too-large grid gives the null model (0 vars, R2 0), a too-small grid gives an unpenalized overfit (119 vars, IS R2 0.52, OOS R2 -0.4). The optimum must lie in the middle of the grid. (The slide's own expanding-window alphas sit at the top edge of 2**linspace(-10,-1.3,50).) [ L5 p.27, 37-39, 53 ]
  ! CV is time consuming and unstable; screening variables on the full sample and then validating is cheating; never use the same data twice. [ L5 p.41 ]
  ! AIC overfits in high dimensions: it is good only for big n/df, not just big n. With 743/119, AIC selects 57 vars and gets OOS R2 -0.22. [ L5 p.43, 45-46 ]
  ! LassoCV on pre-scaled training data scales the validation folds with their own statistics (leakage); implement CV with lasso_path and training-only scaling. [ L5 p.47 ]
  ! CV is usually not valid for time-series data; keep the same starting point in expanding windows. [ L5 p.48, 50 ]
  ! Test-set predictions have nothing to do with choosing alpha; you must not use test data when constructing the model. [ L5 p.52, 55 ]
  ! A random fold on time-ordered data sees the future: validation error looks too good at small alpha, so the procedure under-regularizes (23 vs 15 vars), costing 0.036 of R2_OOS. The bias makes CV scores optimistic. [ L5 p.56 ]
  ! The test-block mean is not a legitimate R2 benchmark; negative R2 must be reported; don't quietly switch benchmarks; disclose the search size; R2 far above 0.3-0.5% monthly on financial data signals a leak. [ L5 p.57 ]
  ! Five leakage patterns: transform (scaler/imputation/PCA/winsorisation) fitted before the split [fatal]; merge on period-end instead of publication date; random fold on time data [fatal]; threshold or hyperparameter chosen on the test block; benchmark changed after the fact. [ L5 p.58 ]
  ! AI-written code: train_test_split default shuffle=True, and StandardScaler().fit_transform before the split. Neither raises a warning and both produce a number, so read code before running it. [ L5 p.59 ]
  ! (Derived from p.57) sklearn r2_score/model.score use the test-block mean as benchmark, so compute R2_OOS manually against zero or the trailing mean. [ L5 p.57 ]

################ L6: Lecture 6: Classification (logistic regression, KNN, from probabilities to decisions, confusion matrix, ROC/AUC, precision-recall, lift)
TOPICS: Logistic regression model and logit link (L6 p.3-6) | Estimation with statsmodels GLM, coefficient interpretation, dispersion check (L6 p.7-11, p.16) | MLE, deviance, null deviance and deviance R^2 (L6 p.10, p.12-14, p.18) | Gradient descent (L6 p.15) | Out-of-sample validation via random hold-out (L6 p.17-18) | Classification risk and Bayes classifier (L6 p.19-22, p.43) | K-nearest neighbours (L6 p.23-28, p.35-37) | Lending Club case design: time-ordered split and training-only preprocessing (L6 p.29-34) | Logistic regression as a classifier vs KNN; sklearn default penalty; polynomial boundaries (L6 p.38-42) | From probabilities to decisions: error types, asymmetric costs, cost-matrix threshold (L6 p.43-47) | Confusion matrix, FPR/FNR, sensitivity/specificity (L6 p.48-51) | ROC, AUC, precision-recall with rare events, precision@k and lift (L6 p.52-56) | Reporting a classifier (checklist) (L6 p.57)
-- CONVENTIONS
  * Classifier quality is misclassification risk P(Y_new != f(x_new)), estimated as the proportion of wrong labels on a validation/test set (out of sample), never in sample. [ L6 p.19 ]
  * Accuracy must be reported with the majority-class rate next to it. The trivial majority rule is the benchmark; on Lending Club it is 83%, and 20-nn (0.83) and logit (0.82) did not beat it at the 0.5 cut-off. [ L6 p.36, p.42, p.49, p.51, p.57 ]
  * Time-ordered data are split by date: every training observation precedes every test observation, 'as it would be if the model were put to use'. The test-sample metric is the relevant one. [ L6 p.29-30, p.54 ]
  * All preprocessing is learned on the training sample only (median imputation, dummy definitions) and the same transformation is applied to the test sample. [ L6 p.30 ]
  * Do not use another model's output as a predictor (LC's grade, sub_grade, int_rate are excluded and used only for comparison). [ L6 p.30-33 ]
  * Logistic regression house style is statsmodels smf.glm(..., family=sm.families.Binomial()).fit(). Check that the dispersion parameter equals 1. predict() returns probabilities. [ L6 p.8, p.11, p.16 ]
  * sklearn LogisticRegression is ridge-penalized by default; set penalty=None to obtain the MLE. [ L6 p.38 ]
  * Deviance R^2 = 1 - D/D0, where D0 is the deviance of the constant prediction ybar. The same structure is used out of sample (the slide does not say which ybar; L4 uses the training mean). [ L6 p.13, p.18 ]
  * Standardize features (StandardScaler, divide by sd) before distance-based methods like KNN. [ L6 p.23 ]
  * Default decision rule is the Bayes rule P_hat > 0.5 (minimizes misclassification). With asymmetric costs, the threshold comes from the cost matrix (lend iff p < 1/5), fixed ex ante; the test-sample optimum 0.195 serves only as a check. [ L6 p.43, p.46-47 ]
  * Positive class = the bad/rare event (default = 1, charged-off = 1). The confusion matrix has rows actual and columns predicted: [[TN, FP],[FN, TP]]. FP = Type I, FN = Type II. [ L6 p.7, p.29, p.44, p.48-49 ]
  * With rare events report precision and recall (PR curve) in addition to ROC/AUC, because AUC is invariant to class proportions. [ L6 p.55, p.57 ]
  * Compare the model against a simple benchmark model or rule: lend-to-everyone profit, or a mort_acc+dti logit AUC of 0.58. [ L6 p.47, p.54 ]

  ! Random splits change results from run to run ('Since the sample is random, you might get different results'), so set seeds. [ L6 p.18 ]
  ! Check the dispersion parameter = 1 to be sure you actually ran logistic regression. newdata must match the format of the original data. [ L6 p.11, p.16 ]
  ! Scale matters for KNN distances; standardize first. [ L6 p.23 ]

################ L7: Lecture 7: Clustering (Dacheng Xiu, Sep 21 2026) - mixture models/GMM, K-means, spectral clustering, hierarchical clustering
TOPICS: Supervised vs unsupervised dimension reduction; clustering vs classification (3-8) | Mixture model and Gaussian mixture model (GMM, fitted by EM) (9-14) | K-means objective and algorithm (15-22) | Standardization before K-means (23, 32) | MNIST case: clusters used as a classifier via majority label (24-28, 31) | Choosing K: interpretability, CV difficulty, AIC/BIC (29-31) | K-means implied model and failure modes (32-37) | Spectral clustering (similarity graph and graph Laplacian) (38-47) | Hierarchical (agglomerative) clustering and dendrograms (48-53)
-- CONVENTIONS
  * Unsupervised learning = models for x alone. It is still judged by 'low deviance, without overfit'. [ L7 p.3 ]
  * Clustering is not classification. When group labels are known (e.g. given asset classes, Purchased), it is a classification/grouping problem, not clustering. [ L7 p.4 ]
  * Clustering is primarily exploratory/descriptive. Choose K so the clusters make sense. [ L7 p.5, p.19, p.29, p.30 ]
  * K-means requires numeric/continuous features and works worse for dummies or counts. [ L7 p.15, p.22, p.32 ]
  * Standardize each feature before K-means: x_tilde = (x - xbar)/sd(x), because K-means assumes equal variance across dimensions. [ L7 p.23, p.32 ]
  * Run K-means from multiple random starts and keep the solution with the smallest within-cluster SS (mixture deviance). [ L7 p.19, p.21 ]
  * K-means deviance = total within-cluster SS (sklearn inertia_). IC df = K x p. Use the usual AIC/BIC (from L4), but treat them as rough and lower quality than in regression. [ L7 p.18, p.22, p.30 ]
  * Prefer an interpretable K over the IC optimum. On MNIST, BIC=30 and AIC=130 are 'way more complicated than is useful'. AIC picks larger models than BIC. [ L7 p.31 ]
  * Cluster-based prediction: predict each cluster's majority label, and report accuracy on both the training set and a held-out test set. [ L7 p.25, p.31 ]
  * Spectral clustering: use the K smallest Laplacian eigenvectors and K-means on their rows. Choose K from the number of near-zero eigenvalues (the eigengap). With a connected graph, skip the constant first eigenvector and use the second. [ L7 p.41, p.42, p.46 ]
  * Hierarchical clustering: focus on agglomerative. Obtain clusters by cutting the dendrogram horizontally. The similarity measure determines the merges. [ L7 p.49, p.51, p.52 ]
-- PITFALLS
  ! 'Clustering should not be confused with classification!' Known labels mean supervised learning. [ L7 p.4 ]
  ! The GMM likelihood is not unimodal and may get stuck in local optima. [ L7 p.12 ]
  ! The K-means solution depends on the start location. Try multiple starts and take the best (lowest WCV). A single start (n_init=1) can give a worse solution (WCV 22.18 vs 16.13). [ L7 p.19, p.21 ]
  ! Scale matters: an unstandardized feature with a larger scale dominates distance and cluster membership. Standardize. [ L7 p.23, p.32 ]
  ! K-means implicitly assumes independent dimensions with equal variance. It fails on non-convex shapes (rings, moons), unequal variances and anisotropic data. On two rings it gets only 51% right. [ L7 p.32-37, p.42 ]
  ! K-means does a worse job when x is made of dummies or counts. [ L7 p.32 ]
  ! CV for choosing K is problematic because the cluster membership k_i is latent. There is no ground-truth y. [ L7 p.29 ]
  ! AIC/BIC assumptions are only roughly true for K-means. The tools are lower quality than in regression and can choose far too many clusters (MNIST AIC=130). Descriptive intuition is often better. [ L7 p.30-31 ]
  ! Do not over-interpret clusters (xkcd K=3 cartoon). Clusters can be impure: the MNIST '1' cluster is only 5 of 10 ones. [ L7 p.27-28 ]
  ! For a connected graph, the first Laplacian eigenvalue is 0 with a constant eigenvector that 'says nothing'. Use the second eigenvector. [ L7 p.46 ]
  ! The choice of similarity/dissimilarity measure determines the clustering result and how hierarchical merges happen. [ L7 p.8, p.48, p.52 ]
