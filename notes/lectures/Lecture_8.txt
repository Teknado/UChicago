Tree-based Statistical Learning
Tree-based learning: predicting outcome y from predictors x = (x1, ..., xp)
′ by dividing up the
feature space into small regions where the outcomes are more similar.
Within each region, a very simple model is fit locally.
This works both when y is categorical and continuous, i.e., both for classification and regression
Regions can be achieved by making successive binary splits on the predictors variables x1, ..., xp,
i.e. we choose a variable xj, j = 1, ...p, divide up the feature space according to
xj ≤c
and
xj > c
Then we repeat the same on each half.

Two types of likelihood:

Classification trees have class probabilities at the leaves.

Regression trees have a mean response at the leaves.

===== PAGE 8 =====
Classification Trees
Classification trees are popular because they are interpretable (they mimic how decisions are
made).
▶In classification, yi ∈1, ...K are the class labels, and xi ∈Rp measure the p predictor
variables.
▶The classification tree can be thought of as defining m regions (rectangles) R1, ...Rm, each
corresponding to a leaf of the tree
▶We assign each Rj a class label cj ∈1, ...K (typically the most dominant class within the
region).
▶We then classify a new point x as cj if it falls in region Rj .

===== PAGE 21 =====
How to Build Trees?
There are two main issues to consider in building a tree:
▶How to choose the splits?
▶How big to grow the tree?
Think first about varying the depth of the tree ... which is more complex, a big tree or a small
tree? What tradeoff is at play here? How might we eventually consider choosing the depth?
Now for a fixed depth, consider choosing the splits. If the tree has depth d, then it has about
2d nodes. At each node we could choose any of p the variables for the split—this means that
the number of possibilities is
p · 2d
This is huge even for moderate d! And we haven’t even counted the actual split points
themselves

===== PAGE 22 =====
CART
We estimate decision trees by being recursive and greedy
CART grows the tree through a sequence of splits:
▶Given any set (node) of data, you can find the optimal split (the error minimizing split)
and divide into two child sets.
▶We then look at each child set, and again find the optimal split to divide it into two
homogeneous subsets.
▶The children become parents, and we look again for the optimal split on their new children
(the grandchildren!).
You stop splitting and growing when the size of the leaf nodes hits some minimum threshold
(e.g., say no less than 10 obsv per leaf).
Often there are also minimum deviance improvement thresholds.

Trees provide Automatic Interaction Detection
For example, different genres are more/less dependent on GRP.
AID was an original motivation for building decision trees. Older algorithms have it in their
name: CHAID, ...
This is pretty powerful technology: nonlinearity and interaction without having to specify it
in advance. Moreover, nonconstant variance is no problem.
Methods with these characteristics are called nonparametric.
No assumed parametric model (eg, y = xβ + ε, ε ∼N(0, σ2)).

===== PAGE 29 =====
Pruning via Minimal Cost-complexity Algorithm
Biggest challenge with such flexible models is avoiding overfit. For CART, the usual solution is
to rely on out-of-sample prediction.
The minimal cost-complexity pruning algorithm, like LASSO, is parametrized by a complexity
parameter α.
Rα(T) = R(T) + α|T|
Pruning yields candidate trees, and we use a testing sample to choose.

===== PAGE 40 =====
The Problem Is Not Bias. It Is Variance.
Cross-validated pruning gave us a 211-leaf tree with out-of-sample R2 = 0.7220. That is the
best single tree there is, and it is still not good enough.
▶A deep tree can approximate almost any function — grown out, ours interpolated all
20,640 tracts.
▶What it cannot do is give you the same function twice. The greedy first split is a choice
between close competitors; if a resample flips it, every split below it changes.
▶Prediction error decomposes as (bias)2 + variance + noise, and for a deep tree the middle
term dominates.
Cross-validation picks the depth that minimizes average out-of-sample error. It does nothing
about the dispersion at that depth — and with one history you only get one draw.

Unfortunately, it is tough to avoid overfit with CART:
Deep tree structure is so unstable that optimal depth is not easily chosen via cross validation,
and there’s no theory to fall back on.
Instead, we can average over a bootstrapped sample of trees:
▶repeatedly re-sample the data, with-replacement, to get a ‘jittered’ dataset of n
observations.
▶for each resample, fit a CART tree.
▶when you want to predict y for some x, take the average prediction from this forest of
trees.
Real structure that persists across datasets shows up in the average. Noisy useless signals will
average out to have no effect.
This is a Random Forest

===== PAGE 43 =====
Step 2 Is the Whole Difference
Drop step 2 and you have bagging: bootstrap, fit, average. Keep it and you have a random
forest. The gap between them is worth understanding.
▶Bagged trees are correlated. They all see nearly the same data, so they all find nearly
the same strong first split. Averaging B estimators cuts variance by about B only if they
are independent; averaging correlated things buys much less.
▶Starving each split of columns decorrelates them. Offer only a random subset of
predictors at every split — √p for classification, p/3 or p for regression — and the trees
are forced to disagree.
▶The price is a little bias per tree. Sometimes the best split really was the one you hid.
That is a good trade: bias is small and shared, variance is large and cancels.

===== PAGE 44 =====
Understanding Random Forests
Recall how CART is used in practice.
▶Split to lower deviance until leaves hit minimum size.
▶Create a set of candidate trees by pruning back from this.
▶Choose the best among those trees by cross validation.
Random Forests avoid the need for CV.
Each tree ‘b’ is not overly complicated because you only work with a limited set of variables.
Your predictions are not ‘optimized to noise’ because they are averages of trees fit to many
different subsets.
Each tree is grown deep and not pruned — the averaging does the regularizing. In practice you
set B as large as your patience allows, set a minimum leaf size, and stop.

Model Averaging
This technique of ‘Model Averaging’ is central to many advanced nonparametric learning
algorithms.
ensemble learning, mixture of experts, Bayesian averages, ...
It works best with flexible but simple models
Recall lasso as a stabilized version of stepwise regression (if you jitter the data your estimates
stay pretty constant).
Model averaging is a way to take arbitrary unstable methods, and make them stable. This
makes training easier.
Probability of rain on a new day is the average P(rain) across some trees that split on forecast,
others on sky. We don’t get tied to one way of deciding about umbrellas.

===== PAGE 50 =====
Ensemble Learning with Boosted Trees
“Boosting”: Ensemble method for aggregating many individual “weak learners” (models that don’t
forecast well) into a single “strong learner”. Cf. Schapire (1990, ML)
Algorithm Sketch:
▶Fix tree-depth L (shallow!, e.g. L = 1)
1. Fit 1st simple tree
▶Forces trees to be weak learners with large bias
2. Fit 2nd shallow tree to residuals from the first tree
▶Forecasts from the two trees are summed to form the ensemble prediction
▶Shrink the forecast component from the 2nd tree by a factor ν ∈(0, 1)
▶Helps prevent the model from overfitting the residuals
▶Iterate until there are a total of B trees in the ensemble
L, ν, and B are tuning parameters selected via validation.

===== PAGE 55 =====
The Honest Version of “Boosting Wins”
Boosted trees are the standard workhorse on tabular data, and that reputation is earned. But
state it precisely:
▶A random forest is nearly tuning-free. Set B large, set a minimum leaf size, walk away. On
this panel that gets you 0.8327.
▶Boosting is not. With ν, B, depth and subsampling all live, the out-of-the-box call sits
0.03 below the forest. The win of +0.027 is real, and it is bought with a validation budget.
▶And a tuning budget is a leakage risk. Every round of the search looks at held-out data.
Tune on a validation split, report on a test split you touched once.
If you have a day, boost. If you have an hour, or a deadline, or a committee, the forest is the
better answer and it is not close.

===== PAGE 56 =====
Variable Importance
The mean decrease in impurity (MDI) importance of a feature is computed as follows:
1. For each tree in the forest:
▶The decrease in variance for a feature used in a split is calculated every time that feature is
used to split a node.
▶The decrease is a measure of how much that split improves the homogeneity of the node,
specifically, how much the impurity of the target variable is reduced as a result of the split.
▶This decrease in impurity is averaged across all the splits in the tree that use the feature.
2. For the entire forest:
▶The average decrease in variance for each feature is then averaged across all the trees in the
forest to give a final importance score for each feature.
3. Normalization:
▶The feature importance scores are then normalized so that they sum to 1.
Note what this is not: every quantity above is computed on the rows the tree was fit to. MDI
is an in-sample statistic.

===== PAGE 57 =====
Permutation Variable Importance
Permutation-based feature importance is model-agnostic and is often more reliable, especially
in the presence of correlated features. This method involves the following steps:
1. Train the model on the original dataset and compute the performance metric of interest
on held-out data.
2. For each feature:
▶Shuffle the values of the feature across all samples, thereby breaking the relationship
between the feature and the target.
▶Recompute the performance metric of the model using this modified dataset.
▶The importance of the feature is how much the metric decreases. A larger decrease indicates
a more important feature.
3. Repeat the shuffle several times and average, since a single permutation is itself a random
draw.
Permutation importance is more computationally intensive than MDI because it requires
re-evaluating the model for each feature — and it is worth it, because it answers the question
you actually asked.

===== PAGE 61 =====
Roundup on Tree-based Learning
We have seen three techniques for building tree models.
▶CART: recursive partitions, pruned back by CV.
Readable. Unstable. On the California panel, R2 = 0.7220.
▶Random Forest: average many deep CART trees, decorrelated by column subsampling.
Nearly tuning-free, and R2 = 0.8327. The default answer.
▶Boosted Trees: repeatedly fit shallow trees to residuals, shrinking each by ν.
Best in class at 0.8600 — after ν and B are chosen honestly. Out of the box it loses to
the forest.
Trees are poor in high dimension, but fitting them to low-dimensional factors (principal
components, Lecture 1) is a good option.
And whichever you pick, you have bought accuracy with interpretability. Permutation
importance and partial dependence are how you buy some of it back.
